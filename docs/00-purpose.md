# 项目目标 · 宗旨

**真源：** 本节「宗旨」与根目录 [`README.md`](../README.md)、[`AGENTS.md`](../AGENTS.md) 同文。下文是第一性推理，用来拒绝无关优化；不另立一套架构铁则。铁则仍以 `AGENTS.md` §0 为准。

选定：2026-08-25。

---

## 宗旨

**让长篇小说在跨章、跨会话、跨模型之后，仍然是同一本可审计的书。**

可观察的完成态：正典冻结且关键设定带证据；状态反映此刻；原作不被覆盖；续写 / 改写能对照这份书检查。聊天可以丢，换一个 Agent，书还在。

---

## 1. 要解决的问题（不是手段）

作者用 AI（或不用）写长篇时，**书没有一份耐久、可审计的对象**：

- 设定在聊天、网页 Codex、笔记和正文里各有一份，说不清从哪来。
- 正典（文中已成立的事实）和状态（此刻如何）搅在一起，或者写完不回写，下一章对着过期卡生成。
- 原作和续写覆在同一份稿上，无法回到「未改之前」。
- 换模型、压缩上下文、关会话，记忆消失；下一章像在写另一本书。

市面上常见的两种反应都不对准这个问题：把下一章写得更顺（生成器）；把设定做成网页里的另一份百科（平行真源）。开源这边多是再吐一堆章节。散文质量、日更速度、出版发行，都是别的问题。

**手段（服务宗旨，不是宗旨本身）：** 一书一文件夹；对这份数据只发指令；Coding Agent 凭仓库规约执行。文件夹若不能让书保持可审计，就只是目录，不是答案。

---

## 2. 终局目的（可拒绝测试）

一年后用事实判断做对还是做错：拿一本真实长篇（不是三章 demo），换 Agent、隔会话，仍然能指出设定证据、对上此刻状态、原作完好、续写可检查。

能据此**当场拒绝**的例子：

| 提议 | 拒因 |
|------|------|
| 一键生成全书 / 百章连写 | 产出文本，不保证书仍可审计 |
| 网页 Codex / 数据库与文件夹并行当真源 | 第二份真相 |
| 去 AI 味、绕平台检测 | 不改善「是不是同一本书」 |
| 内置专用模型当护城河 | 模型可换；书对象不能换 |
| 云同步作为写作真相 | 同步可以是副本，不能当真源 |
| 为小白做所见即所得壳，却把文件变成实现细节 | 壳若另立真源，宗旨失败 |

不拒绝、且能从宗旨推出来的例子：场景/节拍落盘、章后状态回写、角色声音样本、带证据的旧稿抽取、句段改写另册。它们让书在作者实际工作的粒度上仍可审计。

## 3. 不可交换边界

实现可换（语言、CLI、阅读器、导出格式）。下列即使能换来局部便利也不能牺牲——即 `AGENTS.md` §0 架构铁则，此处不复述条文。

从宗旨推出的边界含义：

- **单一真源：** 同一事实不允许聊天、UI、导出物各自为政。
- **语义不被实现改写：** 降级、摘要、检查失败不得假装「已对照过」。
- **人的最终裁决权：** 模型可判断，改设定、覆盖原作、跨书写入必须可追溯或经人确认。
- **原料不是指令：** 正文里的 jailbreak 当小说。

铁则与宗旨冲突时，以铁则为执行边界（铁则就是这条宗旨的不可交换形式）。新功能先问宗旨，再问是否破铁则。

---

## 4. 逻辑空间：我们管什么 / 不管什么

原子对象是 **「这本书作为可审计对象是否还成立」**，不是功能按钮、不是模型、不是页面。

| 分区 | Owner | 例子 |
|------|--------|------|
| **书对象完整性** | 本项目核心 | 正典/状态/原作分家；证据；分册；一书一沙箱 |
| **对书的指令** | 本项目核心 | ingest / parse / continue / rewrite / check / export，落在 `books/<id>/` |
| **散文质量** | 作者 + 模型（本项目最多给对照物） | 文笔、节奏、是否「像人」 |
| **规划方法论** | 作者（本项目可存 brief，不强制流派） | Save the Cat、日更、爽点 |
| **发行** | 作者工具链 | KDP、封面、有声；导出可以做，发行不是宗旨 |
| **编辑器壳** | 方向 B，非一期 | 可视化 Codex、云协作 |

关系：壳、导出、模型是 **依赖** 书对象（没有书对象它们无意义），与书对象 **不是** 同级目的。换「有没有 GUI」不会改变「书在不在文件夹里」；反过来，若文件夹不再是真源，GUI 再完整也失败。

**未覆盖（residual，诚实标出）：** 不会用文件夹的作者；需要手机随手改设定的人；要把两本书做成共享宇宙却尚未显式声明系列。这些需求真实，不假装已被宗旨覆盖。系列共享只能作为 **显式声明后的只读借用**，默认仍隔离。

## 5. 当前主矛盾（会变；本次已具名）

**2026-08-25：** 宗旨长期被写成手段（「做成工程文件夹」「Agent-native」），功能清单无法拒绝「再做一个写作产品」。先把问题钉成可审计的书对象。

写入之后，**下一阶段**（本文不修代码）的主矛盾候选：文件夹形状已在，操作层仍按整章、状态靠人记得改——长篇一压，L2 会腐烂。那是场景粒度、回写、声音、可审抽取的事，从本宗旨推出，仍属方向 A。

优先级依据（本次）：因果上游（目的写错则下游全漂）> 长期防腐（防第二真源）> 终局效果。不把「体验」排在可拒绝测试之前。

| 先修 | 后修 | 暂不修（已看见） |
|------|------|------------------|
| 宗旨写清：问题是书对象，不是文件夹本身 | 场景/节拍、章后回写、声音与禁模式、可审抽取、句段改写契约 | 可视化 Codex、云同步当真源、一键全书、去检测、网文日更工厂 |

## 6. 反例（已过）

- **双命中：** 「把书收成 git 文件夹」既像目的又像手段 → 已拆开：目的 = 可审计的书；文件夹 = 手段。
- **零命中：** 「换 Agent 后设定还在」若只写文件夹、不写可审计，会被「空目录也算成功」钻空 → 完成态写了证据/状态/原作/可检查。
- **边界切换：** 阅读器、导出、ST 世界书 —— 它们是指令产物；一旦被当成可改的真源，就越界。切换条件：是否允许在 `books/<id>/` 之外写入设定或正文。
- **失败穿透：** `quality` / `check` 失败不得改口成「已经对照过」；缺 brief 是警告，缺 `kind` 是错误。摘要不得冒充正典。
