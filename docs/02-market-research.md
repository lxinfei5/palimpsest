# 市场调研：商业闭源 vs 开源 AI 小说写作（2026 快照）

> 调研方式：Web 搜索 + X 语义/关键词检索（2026-08）。  
> 目的：格局图；决策已收敛为 **Palimpsest · 方向 A**（见 `03-direction-a.md`）。  
> 非投资建议；产品形态与价格可能快速变化。

---

## 1. 商业产品长什么样

### 1.1 英文市场：Fiction-first 工具带

| 产品 | 模式 | 核心卖点 | 典型能力包 |
|------|------|----------|------------|
| **Sudowrite** | 订阅 + 自有/精选模型（如 Muse） | 散文质量、从梗概到成稿引导 | Story Bible、Story Engine、Write/Describe/Expand/Rewrite、画布规划 |
| **Novelcrafter** | 低订阅 + **BYOK** | Codex（结构化故事圣经）+ 写作环境 | Codex wiki、场景/节拍、自定义 prompt、多模型切换 |
| **NovelAI** | 订阅 + 自研模型 | 创作自由度、少审查、微调模型 | Lorebook、故事续写、图像周边 |
| **RaptorWrite** | 软件免费 + BYOK（常走 OpenRouter） | 零软件费、作者向工作区 | 多文档、上下文控制、场景管理；进阶常绑定课程生态 |
| **Squibler / Inkfluence 等** | 订阅 | 大纲→章节批量生成、结构向导 | 全书生成、导出、类型模板 |
| **Novarrium 等新玩家** | 订阅 | 长篇一致性（如 logic-locking 类叙事） | 强调跨章不矛盾 |

**英文市场共识（综合评测与社区讨论）：**

1. **Sudowrite** ≈ 「散文与灵感助手」标杆：场景草稿、扩写、改写强；长篇一致性仍常被吐槽。  
2. **Novelcrafter** ≈ 「世界构建 + 可控 AI」：Codex 被反复点名为最大差异点；BYOK 降低锁模型焦虑。  
3. **NovelAI** ≈ 「少限制 + 模型控」：适合黑暗/成人向与深度调参用户；工程型大纲弱于 Codex 系。  
4. **RaptorWrite** ≈ 「免费壳 + 自备钥匙」：拉低试用门槛；能力深度与 polish 通常不如付费旗舰。  
5. 纯 ChatGPT/Claude 仍被大量作者当「思考伙伴」用，但缺专用 Story Bible / 场景结构。

### 1.2 商业工具的能力抽象（要对齐的「功能面」）

闭源产品虽 UI 不同，能力面高度同构：

| 能力层 | 具体表现 |
|--------|----------|
| **故事圣经** | 角色、地点、物品、设定；写作时自动/半自动注入 |
| **规划** | 梗概 → 大纲 → 章纲/Beat → 场景 |
| **生成动作** | 续写、扩写、改写、描写强化、对话润色、卡点推进 |
| **一致性** | 人名锁定、设定召回、部分产品做矛盾检测 |
| **文风** | 样本文学风格、tone 预设、作者 voice |
| **工程体验** | 多文档、场景卡片、导出 DOCX/EPUB、系列共享设定 |
| **模型策略** | 托管模型 vs BYOK；审查强度差异极大 |
| **商业模式** | 月费积分 / 订阅档位 / 免费+BYOK / 平台作者工具绑定 |

### 1.3 中文市场：平台助手 + 独立工具 + 灰色生态

| 类型 | 代表 | 特点 |
|------|------|------|
| **平台内嵌助手** | 阅文「作家助手/妙笔」、番茄 AI 扩写续写、七猫 AI 小助理、中文在线逍遥大模型等 | 绑定平台作者流；能力多为灵感、命名、润色、大纲；同时平台严查「AI 水文」 |
| **独立 Web 写作站** | 蛙蛙、火龙果、言笔等（媒体报道常见） | 偏「高产网文」：批量、去 AI 味、绕检测等——伦理与合规风险高 |
| **编辑器/通用 AI** | 各类写作猫、通用大模型 App | 非小说专用；长篇一致性弱 |

**中文格局要点：**

- 平台态度分裂：**一边推 AI 辅助，一边打击纯 AI 低质连载**（晋江等对「叙事原创性」红线更硬）。  
- 争议焦点曾包括：作品是否用于训练协议、AI 文泛滥、检测误伤。  
- 真正「开源、本地、可自托管、能力对齐 Sudowrite/Novelcrafter」的中文产品仍稀缺。  
- 职业网文需求更偏：**日更、类型套路、卡点、去 AI 味**；严肃长篇更偏：**设定一致、文风、可修订**。

## 2. 开源项目长什么样

### 2.1 代表性开源/开源周边

| 项目 | 侧重 | 成熟度印象 |
|------|------|------------|
| **YILING0013/AI_NovelGenerator** | 多章节自动生成、上下文与伏笔衔接 | 中文社区常见入门项目 |
| **RhythmicWave/NovelForge** | 卡片式、JSON Schema 结构化生成、世界观 | 偏「长篇结构化」新一代 |
| **ExplosiveCoderflome/AI-Novel-Writing-Assistant** | Agent + 世界观 + RAG + 整本生产链 | 明确 AI-native 全流程叙事 |
| **ponysb/91Writing（91写作）** | Vue 全栈工具链：长短篇、拆书、prompt、用量统计 | 产品形态完整的中文 Web 开源 |
| **BlinkDL/AI-Writer / RWKV 系** | 中文网文向生成模型 | 模型侧遗产；应用层较旧 |
| **KoboldAI / SillyTavern 等** | 本地故事/角色扮演前端 | 生态强，**非**专业书稿工程 |
| **Scrivener 等传统软件** | 非 AI 或插件 AI | 工程编辑标杆，但不是开源 AI 助手 |

### 2.2 开源相对商业的共性短板

1. **一致性引擎弱**：多数停在「多轮 prompt + 简单记忆」，缺 Canon/Continuity 双轨与证据链。  
2. **工程可维护性差**：生成一堆章节后难修订、难 diff、难协作。  
3. **Agent 契约不清晰**：功能按钮背后没有稳定 I/O schema。  
4. **模型与提示锁死**：部分项目写死某一 API；扩展性差。  
5. **合规与示例数据混乱**：demo 夹带版权文本或成人库，难以正经开源运营。  
6. **UX 两极**：要么纯脚本/CLI，要么薄壳 Web，缺少 Novelcrafter 级 Codex 体验。

### 2.3 开源相对商业的真实优势

1. **数据本地、可审计**（对严肃作者与企业合规重要）。  
2. **BYOK / 本地模型**，不被积分焦虑绑架。  
3. **可被 Coding Agent 驱动**（文件树 + schema 比闭源 Web 更适合自动化）。  
4. **可社区扩展**（导出格式、题材包、审校插件）。  
5. **无内容审查绑架**（需自建安全策略与法律边界说明）。

## 4. 社区与舆论信号（X / 评测综合）

- 作者讨论焦点：**散文质量、长篇不崩、BYOK、价格、审查**。  
- 「最好的单一工具」无共识：有人要 Muse 文笔，有人要 Codex 结构，有人要 NovelAI 自由度。  
- 开源叙事在写作圈弱于编码圈；写作用户更认**成品体验**，不认 star 数。  
- 中文圈对「AI 水文 / 去 AI 味 / 平台检测」噪声大；**认真做 helper 应远离绕检测赛道**，站在「人机协作、可修订、可证明设定来源」一侧。

## 5. 格局结论（给决策用）

### 5.1 市场空位（相对清晰）

1. **本地优先 + 开源 + 长篇一致性** 的正经产品仍少。  
2. **文件/仓库为真相源、Agent 可操作** 是材料独有优势，商业 Web 难抄透。  
3. **Canon / Continuity / Evidence** 三件套可做成学术级/硬核作者级差异点。  
4. **中英双语与网文类型模板** 若做深，可同时服务中文作者与英文 worldbuilding 党。  
5. **兼容 ST 资产** 能借现成社区，但产品叙事应是「小说工程」，不是「又一个酒馆」。

### 5.2 不建议的方向

- 再做一个「闭源积分制一键万章」的山寨。  
- 以「绕过平台 AI 检测」为卖点。  
- 内置版权书库或定向盗站抓取。  
- 与 ST 直接 fork 抢定位（许可证与产品形态都不划算）。

### 5.3 可选战略分叉（你来拍板）

| 方向 | 像谁 | 核心赌注 | 风险 |
|------|------|----------|------|
| **A. Agent-native 书稿仓库** | novel-lab 产品化 | Coding Agent 用户 + 硬核作者 | UI 对小白不友好 |
| **B. 开源 Novelcrafter** | Codex + 编辑器 + BYOK | 可视化体验对齐商业 | 工程量大 |
| **C. 网文流水线** | 91写作/AI_NovelGenerator 深做 | 中文高产作者 | 易卷入低质内容战 |
| **D. 解析/拆书专家** | 证据链 + 角色世界提取 | 工具型、可组合 | 不是完整写作器 |
| **E. 混合** | A 为核，B 为壳，ST 为导出 | 能力最全 | 范围失控 |

材料更自然导向：**E 的收敛版 = A 为核 + 最小可用编辑/阅读器 + 可选 ST 导出**。

**已选定（2026-08-12）：方向 A** — 产品名 **Palimpsest · 叠简**。详见 `03-direction-a.md`。
